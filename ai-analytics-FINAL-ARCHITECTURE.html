04Self-checking: measured, then cut back to one thing

Three positions in one day, each corrected by measurement. Final answer: mark the answer, never repair it, and only on questions where a wrong number costs money.

A flag is only worth showing if it beats the base rate. 22% of answers on the held-out set are wrong. A detector whose precision is below 22% means a flagged answer is less likely to be wrong than an unflagged one — worse than silence.

DetectorPrecisionRecallFalse alarm on correctVerdict
base rate of a wrong answer22%——the bar
Deterministic invariants — fan-out, lossy-join, parts-vs-whole20%14%16%cut below base rate
Same, restricted to money questions13%20%26%cut anti-informative

2-sample, money questions only50%40%7%ship ~1.5× tokens overall

The deterministic probes were the part I was most confident in, and they are the part that failed. They caught F01 — the query that silently dropped ₹11.98 lakh — which is exactly why a single dramatic catch is not evidence. Across 64 answers they are wrong four times in five, because LOSSY_JOIN cannot distinguish F01's catastrophic dropped rows from M01's correct ones. That ambiguity is in the question's meaning, not in the data.

What ships is one mechanism: on a question that produces money or a ranking, write the query a second time at a different temperature and compare executed results, not SQL text. If they disagree, the number is still shown — with a line under it:

  Referral payout for August is ₹5,34,722.

  ⚠ Worth checking before you act on this — a second, independently
    written query returned a different answer.

Never auto-repair. Regeneration measured net zero three separate times: the errors are systematic, so a second attempt reproduces the same mistake. Detection and repair are different mechanisms with different results, and an earlier draft of this document wrongly collapsed them.

05The failure that defines the design

Asked last month profit how much, it answered "₹11,96,252.28".

Real columns. Correct arithmetic. Clean joins. Plausible number. It is revenue minus referral commission minus clinic payouts — a perfectly good quantity that is not profit, because this business records no costs at all.

No validator, inspector or vote can catch that. Only knowing something true about the business can. So profit routes to a ladder instead:

  Collected in August                         ₹18,93,725
  Less referring-doctor commission            −₹5,34,722   leaves ₹13,59,002
  Less clinic-doctor payouts                  −₹1,62,750   leaves ₹11,96,252
  ─────────────────────────────────────────────────────────────────────────
  That is what remains after the payouts we DO record. It is NOT profit.
  Not recorded anywhere: outside-lab charges, salaries, rent, consumables, utilities.

Every figure is computed in SQL and pre-formatted; the model narrates strings and a deterministic pass strips any sentence containing a rupee figure it was not given. Structural, not a polite instruction.

06Security

A conventional validator leaked 5,451 report bearer tokens, 14 password hashes and 30,581 patient results. The hardened layer blocks all four classes for the cost of exactly one question.

  • analytics_ro — live and verified. Read-only, default_transaction_read_only, 8s statement_timeout, table and column grants. Patient exposes only id, gender, yearOfBirth, ageUnit, createdAt, patientNumber.
  • Deny-list on token/PHI tables and columns; no SELECT *; patient-level tables require an aggregate.
  • Static analysis: comma-joins, JOIN without ON, aggregate without GROUP BY, fan-out shapes. Explicit CROSS JOIN is allowed — it is deliberate syntax and the timeout bounds it.

07Known limits

  • Empty column → confident zero. "How many bills used a coupon" answers 0; couponId is never populated, so 0 means unrecorded, not none. The money case (profit) is fixed by routing; the general class is not.
  • ±2 questions of run-to-run noise at n=32. No single-run difference below that is meaningful. Several claims made during this project were retracted for exactly this reason.
  • Remaining held-out failures cluster in p90-of-a-derived-duration, catalogue anti-joins, self-joins and calendar zero-fill.
  • My own tests were a real error source — two controls were objectively wrong and scored correct answers as failures for several runs.

08Open for you, not for the code

  • Payout reconciliation. "August referral amount" has three defensible answers: ₹4,97,868 recomputed from orders, ₹5,29,871 naive, ₹5,34,722 from the stored ledger — 7.4% apart, 12% on one doctor. Worth settling one month by hand.
  • Unused cost machinery. externalLabId and labCost* are empty on all 30,283 orders, while 1,380 tests are handled externally. Populating them converts profit from unanswerable to answerable.
  • V1 scope — owner-only? And should the owner Money page headline change from net billed to match the AI's net collected default?
