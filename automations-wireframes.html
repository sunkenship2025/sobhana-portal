Automations — wireframes v2

Second pass. Three things changed: Automations moved out of Config Center into its own place under Admin; the builder now reads top-to-bottom as the sentence WHEN → FOR → THEN → CHECK → DO → STOP; and every explanation has been lifted out of the screens into design notes below them. What is inside a frame is what a person sees.

01Where it lives

Admin becomes a group with two children, using the same subItems pattern Workflows and Payouts already use — no new nav primitive. Config Center stays what it is: things you set once. Automations is something you operate.

Automations decide who and when. They use a template to speak, and may issue an offer.

Tab order is Automations · Templates · Offers · Activity, not alphabetical and not equal-weight: templates and offers are resources an automation uses, so they sit behind it and are reachable inline from the builder. You raised this — the fix is the ordering plus the inline links in the builder, not demoting them out of the tab bar, because both also need a place where you can see all of them at once.

The old copy said "Your doctor has advised tests that are still pending" — and this system cannot know that. ClinicVisit stores the doctor, the fee, the ward, the queue state and the token. There is no prescription, no advice, no diagnosis field anywhere. The audience is "no diagnostics since this visit", which includes every patient who came for something that never needed a test, so the message must invite rather than remind.

This is a targeting limit, not only a wording one. The upgrade that would make this the sharpest automation in the product is one checkbox at clinic close — "tests advised" — which narrows the audience from everyone who consulted to everyone who was actually told to go and didn't. Worth doing; not worth blocking V1 on.

Blanks are validated against the approved template when you save: an arity mismatch caught here is a dialog, and caught at send time it is a failure for every patient in the run.

33What these screens still do not show

Absent on purpose, each one argued rather than forgotten: a flow canvas · branch nodes · a segment builder · a clinical rule editor · A/B test arms · an intent classifier · message merging · an approval workflow while only the owner has access · anything that would give the centre a second definition of "revenue today" beside Pulse's. Ten automations from now, if a branch node is genuinely needed three times over, it will be obvious and cheap — steps are an array, and every run carries its own frozen copy of the definition.
