Patient360 — Low-Fi Wireframes

Greyscale layout sketches for owner review before any frontend code. Placeholder data only. Reflects the locked scope decisions (see 04-decisions.md). Color, spacing, and exact components are NOT final — this is about layout, information priority, and which controls live where.

Decisions baked into these frames
  • Read-only for money (Q2): "Collect payment" is a deep-link out to billing, not inline.
  • Due number (Q3/Q11): calculated live; excludes cancelled visits, refunded & failed payments.
  • Results (Q4): timeline shows a generic "⚠ Abnormal results" badge only — no values/test names (open the report PDF for specifics).
  • No duplicate hint (Q5), no deceased banner (Q10), no WhatsApp opt-in gate (Q7) — but the destination number is shown before sending.
  • Delivery status (Q8): Sent → Delivered → Read shown per report (real, from MessageLog webhook).
  • Doctors (Q1): no access — staff/owner only (not depicted).
  • Cancelled visits: greyed + struck, behind a "Show cancelled" toggle, excluded from dues.

Annotations & what's intentionally NOT here
  • "+ New Visit ▾" offers only enabled modules (Axora). Diagnostics-only tenant → Diagnostics only; clinic fields self-hide.
  • Status chips are shown with emoji here purely as low-fi stand-ins; final = text+icon chips (WCAG-safe, no color-only meaning).
  • Report state can be: Finalized v{n}, Partially finalized (X of Y), Bill-only, External-upload pending, Results pending. (backend-dep)
  • Abnormal badge is generic only — no test names or values anywhere on this screen (Q4). Specifics live in the report PDF.
  • Not shown by decision: duplicate/merge hint (Q5), deceased banner (Q10), WhatsApp opt-in gate (Q7), doctor access (Q1), inline payment (Q2), result trend charts (deferred).
  • Backend-dep markers flag data the current API doesn't return yet — these gate the "backend-first" work: Paid/Due/discount/method, abnormal flag, delivery status, partial-report state, cursor pagination.
