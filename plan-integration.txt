Plan: New Architecture Integration — Report Rendering, Result Entry, Billing
The new 3-module architecture (TestDefinition, ClinicalPanel, BillableProduct) is implemented but not yet wired into the existing report rendering pipeline, result entry flow, or bill display. There are 5 bugs/data-loss issues and missing integration paths that need fixing.

TL;DR: Fix layout type enum mismatch, add referenceText + interpretationSeverity to report snapshots, add ClinicalPanel fallback grouping for product-ordered tests, resolve age-aware ranges at entry time for child tests, and add product-grouped bill display.

Steps

A. Fix Layout Type Enum Mismatch (Bug)
In ManagePanelDefinitions.tsx — the LAYOUT_TYPES array uses FLAT and GROUPED which don't exist in the Prisma PanelLayoutType enum, and is missing STANDARD_TABLE and WIDAL. Fix by replacing FLAT → STANDARD_TABLE, GROUPED → STANDARD_TABLE (with subgroups), and adding WIDAL as an option. This ensures Prisma accepts the values and the renderer can match them.

In reportRendererService.ts — the renderPanel() switch already handles all 5 enum values. No change needed here, but verify the default fallback to renderStandardTable covers any edge cases.

B. Add referenceText to Report Snapshot (Data Loss Fix)
In reportSnapshotService.ts — add referenceText: string | null to the TestResultSnapshot interface (around line 40).

In createReportSnapshot() — when building each result object (both panel-linked and orphan paths), include referenceText from resolved ranges: referenceText: resolvedRanges.get(test.id)?.referenceText ?? test.referenceText ?? null.

In buildEphemeralSnapshot() — same change in both panel-linked and orphan test result-building blocks.

In reportRendererService.ts — update renderStandardTable() and renderInterpretationSingle() to display test.referenceText when numeric min/max are both null (similar to how the result entry UI already does it).

C. Capture interpretationSeverity in Snapshot (Bug Fix)
In reportSnapshotService.ts — add interpretationSeverity: string | null to the TestResultSnapshot interface.

In createReportSnapshot() — include interpretationSeverity in each result object push (both panel-linked and orphan paths). Currently the local variable interpretationSeverity is set but never written to the result.

In buildEphemeralSnapshot() — same fix for both paths.

In reportRendererService.ts — update renderInterpretationSingle() to apply severity-based CSS classes to the interpretation block (e.g., interpretation-normal, interpretation-warning, interpretation-critical). Add corresponding CSS rules to report-screen.css and report-print.css.

D. ClinicalPanel Fallback Grouping in Snapshot
In createReportSnapshot() — after the existing panelItems loop (legacy grouping), add a fallback: for tests still orphaned (not linked to any PanelDefinition), look up the LabTest's code in ClinicalPanelItem → ClinicalPanel (via TestDefinition.code match). If found, group under that ClinicalPanel's layout and department.

In buildEphemeralSnapshot() — same ClinicalPanel fallback lookup. This ensures tests ordered via BillableProduct → TestDefinition that have no legacy PanelTestItem entries still get proper panel grouping and layout rendering.

E. Age-Aware Reference Ranges in Result Entry UI
In diagnosticVisits.ts GET /:id handler — after building the transformed response, call resolveReferenceRanges() for all child test IDs with the patient's yearOfBirth and gender. Override each child test's referenceRange with the resolved age-specific values. This way the result entry UI shows the correct age/gender-specific reference range, not just the LabTest default.
