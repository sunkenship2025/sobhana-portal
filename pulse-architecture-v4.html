Pulse — architecture

An analytics agent over a diagnostic centre's live Postgres. 5,446 lines across 27 files. Read-only role analytics_ro. One entry point, one pipeline — the V1 fallback was deleted on 12 Sep 2026.

deterministic — code decides, testable, repeatable model — an LLM decides

The single organising principle: every invariant that matters is enforced in code, not described in a prompt. Each one that stayed in a prompt held until it didn't — the dues definition, the paise convention, "a rate is not a total", three separate rewordings.

02 Knowledge deterministic

knowledge.ts:433,505 — built once at startup (~80s), 819 concepts

Live introspection: schema graph, every Postgres enum, branch codes and names, departments, test codes and test names, payout categories, value index. Plus ~28 hand-written synonyms for words no lookup can discover (lab, scan, cost).

Invariant: the catalogue is an accelerator, never the authority. A term it misses is a lookup failure, never a fact about the business.
Killed: "the system has no report types called reportable, bill only or external" — three real workflowMode values across 30,247 orders. The enums were already in k.enums feeding the SQL writer; the semantic index just couldn't see them.
↓

03 Resolution deterministic

knowledge.ts:582 scoreMatch · 599 resolveRanked · 617 resolveTerm · 703 termsIn

Ranked, no model call: exact 1.00 · normalized 0.95 · prefix 0.75r · word 0.70r · substring 0.40r, where r = min(len)/max(len). Below MIN_CONFIDENCE 0.30 a match is a lead, never a filter.

Invariant: a short code can never outrank a long name it merely begins. ct inside ct-brain plain is 2 chars of 14 → scores 0.107 → never commits.
Killed: CT-BRAIN PLAIN → CT (Clotting Time) → ₹1,918 reported for a test that had billed ₹1,03,400. A 53× error, no hedge, then forced into three later queries as a hard filter.
↓

04 Plan model

analyst.ts:367 askPlan — called with termsBlock(q) + ctx

Declares the goal, the analytical job, the spec (measure / scope / time) and the first steps. Resolution runs before this, so the planner is handed terms already grounded against live data.

Only inferred thing in the whole resolution path: which substring of the question becomes a scope term.

05 Spec grounding deterministic

spec.ts:217 completeSpec · 208 aliasesFor · 122 verifySpec

Every scope term re-resolved against live concepts; the planner's guess is overwritten when resolution succeeds and dropped when the value doesn't exist. Periods resolve to real IST dates. Each constraint carries how, confidence, aliases.

Invariant: a guess may shape a query; only a confident resolution may gate one. Below 0.30 verifySpec will not reject on it.
Killed: {test:'ultrasound'} passed because the dimension name was valid, then got forced into SQL → a confident 0 instead of 265. Same shape as branch='CNT,BLN', which rejected five correct queries.
↓

07 Safety & verification deterministic

validator.ts · sqlscope.ts (pgsql-ast-parser) · spec.ts:122

LayerQuestion it answers
validate()Is this SQL safe? No writes, no bearer tokens, no password hashes, no SELECT *, no comma-joins, no fan-out double counting, no system catalogs. Non-negotiable by role.
exposedIdentifiers()Would it return a person? Only consulted when rowLevel === false. Projected columns, not tables read — a name inside count(DISTINCT …) is a measurement, a name in the select list is a disclosure.
scopeOf()Which predicates restrict the rows the answer is computed from? Walks outward from the result statement through referenced CTEs and subqueries only.
verifySpec()Did the committed scope and period survive into the query?
Invariant: a parse failure is never a rejection — it falls back to string matching. A guard that can refuse a good answer but cannot confirm a bad one is worse than no guard.
Killed: WITH filtered AS (… WHERE test='CTBP') SELECT SUM(price) FROM orders — the literal is present, the CTE is never referenced, the total is over everything, and a string search called it correct.
↓

08 The investigation loop deterministic control, model proposals

run.ts:114–232 · investigation.ts

for each round:
  dispatch steps (pool 3)  ──────────────→  evidence
  recheckScope()           → a better resolution WITHDRAWS what the old one produced
  askInvestigate()         → hypotheses + next steps  (guarded: a parse failure ends the
                              investigation, never the run)
  enforce()                → a claim settled without the analysis it said it needed
                              goes back to OPEN
  measure()                → newEvidence · duplicates · recoveries · requirementsSatisfied
                              · resolvedMaterial · newDimensions → gain

  STOP WHEN   resolved()      nothing material open
              stagnating()    3 rounds earning nothing, OR belief unchanged despite fresh
                              rows, OR no requirement satisfied and no claim settled
              !next.length     and no requirement left to derive a step from
  CEILINGS    12 rounds · 30 calls · 180s  ← emergency brake. Hitting one marks the
                                             answer INCOMPLETE, never a finish.
Invariant: the model may propose; it may not declare itself done. A question that genuinely needs thirty queries gets them.
Killed: stopped at rounds === 8 with both real levers unsized — at 82s of a 180s budget, while 14 of 15 queries were failing invisibly.
↓

09 Job → contract → capability deterministic

contract.ts contractFor · capability.ts renderOptions

Thirteen analytical jobs (magnitude, comparison, composition, concentration, attribution, progression, variability, conversion, relationship, ranking, enumeration, explanation, opportunity) — declared by the analyst, never matched from question words. The contract allocates information: prose carries conclusion and implication, artifacts carry rows. The budget is numbers-per-answer.

Capability matching is a declarative evidence-to-render contract: requires (structural gates) + buildable (can the renderer construct its input?) + expresses. No question text reaches this layer.

10 Write-up model

analyst.ts:395 askResponse · run.ts:310 (retry-guarded)

Segments — verdict, points, caveat, action — plus artifact choices and sized opportunities. One retry on a truncated response, then a deterministic simplify.

Killed: a write-up truncating mid-JSON discarded a completed 118-second investigation. parseLoose now salvages the parseable prefix — but never by closing an unterminated string, because a half-written WHERE would close into SQL that runs and returns a confidently wrong number.

11 Post-checks deterministic

grounding.ts · contract.ts checkAnswer · opportunity.ts

CheckWhat it enforces
groundNumbers()Every figure is exact, derived (a share, difference, sum or % change over two facts — column totals count), ordinary (a small count, a year, a period), or it is sent back.
checkAnswer()Number density, artifact required, rows out of prose. Repair once, then deterministic simplify.
rank()Opportunities ranked rupees × confidence × causality. Unsized candidates are considered, never recommended.
incompleteTravels as data, rendered above the answer — never a regex hoping the writer disclosed it.
Killed: report open-rate ranked above discounting because it sounded actionable — ₹7,400 over 45 days vs ₹1,05,035, and modelled rather than observed.

Data structures

AnalysisSpec

measure · scope[] · time. Each constraint carries term, dimension, value, aliases, how, confidence.

Evidence

tool · ok · summary (formatted, never raw paise) · data.rows · sql · means · recovered · calls.

Investigation

hypotheses with status, material, requires[] · unresolved · contradictions · stoppingReason.

Contract

job · maxNumbers · needsArtifact · rowsInProse · canShow[].

Opportunity

currentValue · estimatedImpact · impactMethod · causality (observed/modeled/causal) · confidence.

PulseTrace

Every decision, per turn, as an audit row: plan, spec, executed steps, render options chosen vs admissible, contract violations, grounding provenance, round-by-round progress.

Known open

  • The spec never reaches the SQL writer. tools.ts:239 calls generate(k, q) — the resolved value, dimension and aliases are discarded, the generator re-derives meaning from English, and the verifier tries to recognise whatever it produced. This is the root of the alias / LIKE-mode / breadth patching.
  • Wall clock. Checked between rounds, so deep investigations reach 160–220s against a 180s ceiling.
  • Renderers under-used. distribution admissible 13×, chosen 2×; compare and chart never chosen. Capability scores cluster at 0.23–0.38 — the ranking doesn't discriminate.
  • Job misclassification. Six of seven "how do I improve" questions classified explanation, not opportunity — so the entire sizing and ranking subsystem stays dormant on the questions it was built for.
  • No feedback signal. No thumbs, no re-ask detection. Every quality judgment so far came from reading logs by hand.

Two things built and never observed firing in production: recheckScope (retroactive withdrawal) and, until 12 Sep, the stagnation detector — which then fired on its first real case and caught a genuine defect.
