013B — can "today, then the box" actually be executed?

Your concern was right to raise. The short answer: yes, because the empty state is not a new feature — it is the STATUS path rendered without narration. Every number on it comes from code that already exists and was already tested. Here is exactly where each piece comes from.

The real risk is latency, not correctness

Six queries on Neon is 1–3 seconds. That is too slow for something that appears on click. Three mitigations, all cheap:

Prefetch on hoverThe 2A tooltip appears at 400ms. Start fetching then. Most opens are preceded by a hover.
Cache 5 minutes per user + branch"Today" doesn't change meaningfully in 5 minutes. Second open is instant.
Box first, numbers slide inNever block the input on the numbers. Show the input immediately with skeleton rows above; fill them as they land. If nothing has landed by 2s, show a plain greeting instead.

The one thing that would make 3B too complex: if the empty-state numbers had to be page-aware in V1 (Payouts page → payout numbers, OPD page → OPD numbers). That multiplies the query sets by the number of modules. V1 locks the empty state to one fixed set — collection, cases, due, late reports — regardless of page. Page-awareness goes in the context bar (which page you're on) but does not change the numbers shown. That keeps it to six queries, one cache key, and one thing to get right.

Verdict on 4B: executable. The backend already returns rows plus metadata (metric, unit, dimensions, period); the shape is decided by a small deterministic function over that metadata, not by the model. Seven components, one overlay. The one place to be careful is which shape wins when a result is ambiguous — e.g. a 2-row list vs a comparison. Rule: if the question named two periods, it's a compare; if the rows are time buckets, it's a series; otherwise a list. That rule is testable against the 123 questions we already have controls for.
