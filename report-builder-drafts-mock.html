Report Builder — Drafts & Publishing

Drafts are saved as inactive panels in the database. A report can never be billed until a product exists, so a draft is always safe. Here's the lifecycle, where drafts appear, and what each one stores.

The lifecycle

The ⋯ menu holds the rarer actions: Discard draft (draft only), Unpublish → back to draft (live only), and Duplicate. Publishing and unpublishing are the only two clicks that change whether the report is usable.

Everywhere else

Panel Definitions — drafts already appear here as Inactive (that's exactly what a draft is). No new place to learn.
Billing / ordering / worklists — a draft never appears, because it has no BillableProduct. That's the hard safety line, not a flag we have to remember to check.
The status chip in the toolbar always tells you the current report's state at a glance: Draft · Live · Billable.

What each draft actually stores

A draft is one inactive ClinicalPanel row + its ClinicalPanelItem rows + a TestDefinition row for each brand-new test (~1 KB each). A 10-test draft is well under ~20 KB; hundreds of drafts are a few MB — DB size is never the issue. The thing we actually manage is clutter: drafts stay out of the live lists, and Discard removes the panel plus any definitions it uniquely created, so abandoned drafts don't pile up. Because no product exists until you publish, a draft can never be ordered or billed.
Draft = inactive panel, no product Live = active panel Billable = has a product
